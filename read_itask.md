# Ведение
## Общая информация
Системный вызов (syscall) — это контролируемый переход из пользовательского режима (ring3) в режим ядра (ring0), чтобы пользовательский код мог:
- печатать на консоль (sys_cputs),
- создавать/убивать окружения (sys_exofork, sys_env_destroy),
- управлять памятью (sys_alloc_region, sys_map_region),
- IPC (sys_ipc_*),
- читать время (sys_gettime),

Главный смысл: пользовательскому коду нельзя позволять напрямую выполнять privileged-инструкции, менять таблицы страниц или читать память ядра.

## Как работает сейчас
В пользовательской библиотеке (lib/syscall.c) вызывается функция
```c
int64_t syscall(uint64_t num, uint64_t check, uint64_t a1,...,a6)
```
Она делает int $T_SYSCALL (у тебя T_SYSCALL == 48), заранее раскладывая аргументы по регистрам. 
CPU делает аппаратный переход через IDT:
- сохраняет RIP, CS, RFLAGS, RSP, SS в kernel stack (через TSS rsp0)
- прыгает в trapentry.S → _alltraps
- _alltraps сохраняет все GPR в Trapframe
- вызывает trap() (C)

В итоге kern/syscall.c делает switch по syscallno и вызывает обработчик. Возврат в user: ```env_run() → env_pop_tf() → iretq```
CPU восстанавливает регистры, сегменты и возвращается в ring3.

INT/IRET — механизм старый и относительно дорогой. Накладные расходы складываются из того, что он аппаратно пушит много состояний, идёт через IDT/stack switch, сохраняется большой trapframe, делает возврат через iretq.

## Механизм SYSCALL/SYSRET
Это современный механизм x86-64, используемый Linux/Windows. Идет через MSR (LSTAR). Stack switch не делается автоматически → ядро обязано вручную, сохраняет минимум регистров. Возврат sysretq проиходит быстрее.

Ключевой момент безопасности: sysret падает #GP, если RIP/RSP неканоничны. Пользователь может специально сделать это и “уронить ядро”, если не сделать проверку → поэтому обязательно нужно проверять адреса перед sysret и иметь fallback (например iretq или kill env).

## Механизм io_uring
Подход через колцевой буфер.
user и kernel разделяют страницу (или несколько), где лежат очередь запросов (SQ), очередь результатов (CQ), head/tail указатели. Пользователь кладет несколько запросов в SQ, затем одним "doorbell"-syscall говорит ядру "обработай".

# Постановка задачи
Смысл задания в том, чтобы все существующие системные вызовы могли быть вызваны через новые механизмы, и потом можно было сравнить накладные расходы.
Требуется модифицировать организацию системных вызовов в JOS. реализовать системные вызовы с использованием современных механизмов и провести замер изменения накладных расходов на выполнение системного вызова и использованием текущего и добавленных механизмов. Два подхода для реализации:
- инструкции syscall/sysret.
- io_uring-подобный подход через кольцевой буфер.

Реализации должны быть безопасными, то есть некорректные действия со стороны пользователя не должны приводить к утечке информации или нарушению работы ядра. Код должен быть работоспособен (в том числе с ASAN/UBSAN) и хорошо структурирован.

# Реализация
1) Старый механизм (INT 0x30)
Пользовательская библиотека (lib/syscall.c) кладёт rax = номер syscalls, rdx, rcx, rbx, rdi, rsi, r8 = аргументы. Делает int $T_SYSCALL (T_SYSCALL=48). Ядро ловит trap T_SYSCALL, в trap_dispatch() вызывает syscall(...). Возвращаемся через iretq.
Однако такие переходы сравнительно тяжелые

2) SYSCALL/SYSRET
Здесь вместо int используется специнструкция CPU. syscall прыгает на адрес из MSR LSTAR, сохраняет user RIP в RCX, RFLAGS в R11, грузит kernel CS/SS из MSR STAR, очищает флаги из FMASK (обычно IF). sysret возвращается в user, используя RCX/R11 как RIP/RFLAGS, CS/SS формируются из STAR (user-селекторы фиксированы).
Однако, RCX и R11 изменяются, поэтому аргумент a2 нельзя передавать в RCX, он переносится в R10 (как в Linux)

3) io_uring-подобный подход (кольцевой буфер)
Чтобы не делать syscall на каждый маленький вызов, пользователь пишет пачку запросов в shared-ring (SQ), делает один sys_ring_enter(), ядро обрабатывает пачку, пишет ответы в CQ, пользователь читает CQ
Тут нужно аккуратно обеспечить безопасность (валидация индексов, perms, запрет “блокирующих” syscalls внутри batch).

## Измерение накладных расходов
Для честного сравнения добавлен syscall SYS_nop, которая ничего не делает и возвращает 0. Далее необходимо выполнить N раз вызов, чтобы усреднить значение накладных расходов.

Для ring: заполнить SQ 32 запросами SYS_nop, сделать один SYS_ring_enter(32), поделить получившиеся cycles на 32.

Останется сравнить int overhead, syscall/sysret overhead, ring amortized overhead.
